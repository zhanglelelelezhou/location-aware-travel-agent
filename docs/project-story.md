# 项目故事

## 一句话版本

我把实习期间验证过的“位置增强翻译”概念，重构成了一个可复现、可评测的位置感知旅行 Agent：它能理解旅行约束、规划工具调用、处理失败，并把执行轨迹暴露出来供调试和评测。

## 背景

跨境旅行中的问题通常不是单纯翻译。例如“附近有没有适合素食者的餐厅，应该怎么用日语询问”同时包含位置检索、偏好过滤、知识判断和语言生成。单次 Prompt 很难稳定完成这类复合任务，也无法解释答案来自哪里。

## 我的任务

设计一个可以运行在服务端、未来可对接穿戴设备的 Agent 后端，并满足三个约束：

1. 工具调用过程可追踪；
2. 外部服务失败时不编造结果；
3. 没有商业 API Key 时仍能本地复现和测试。

## 核心行动

- 使用 LangGraph 把理解、规划、执行、校验、恢复和响应建模为显式状态机。
- 通过统一 Tool 接口隔离 Agent 与 POI、天气、翻译和知识服务。
- 默认提供确定性 fixture，建立稳定的回归测试基线。
- 将执行计划和工具结果写入 trace，为后续错误分析与评测提供数据。
- 把重试限制为一次，避免外部服务故障造成无界循环和成本失控。
- 保留规则 Planner 作为可复现基线，并加入结构化 LLM Planner、Schema 校验、一次定向修复和规则降级。
- 用 20 条开发用例对比规则 Planner 与 DeepSeek：完整任务通过率从 55% 提升到 85%，意图准确率从 55% 提升到 100%，同时记录延迟、Token 和成本。
- 发现第一版标注受到规则实现污染后，保留初始报告，重新定义主任务意图、工具集合和安全约束，并使用已有预测离线重评分，保证实验可审计。
- 将“行程必须同时查询 POI 与天气”等不可协商约束下沉到确定性策略层，并在 trace 中记录每次自动补正。
- 在真实模型运行前冻结 20 条独立留出用例并记录 SHA-256；开发集达到 95%，留出集首次运行达到 85%，相比各自规则基线提高 40 和 35 个百分点。
- 接入 Open-Meteo 真实天气后，用端到端冒烟测试发现“东京”被解析到中国同名地点；没有维护脆弱的别名表，而是改为设备经纬度优先、歧义时失败关闭，并让 Mock 与真实服务共享同一个输出模型。
- 接入 OpenStreetMap Overpass 后，在东京站真实坐标附近返回了带距离、来源和署名的餐厅/咖啡馆；对纯素等偏好只接受 `diet:*` 标签证据，证据不足时明确降级为候选而不是推荐。
- 使用官方 MCP Python SDK v2 将天气和 POI 注册为只读、幂等工具；LangGraph 与 MCP 共用 adapter，并通过内存客户端和真实 stdio 子进程验证工具发现、Schema 校验与结构化结果。
- 增加可切换的 MCP Client 工具注册表，让同一 LangGraph 计划真正经过 `tools/call` 执行；多工具计划复用一个协议会话，协议错误会进入原有 trace 和有界恢复路径。
- 从日本消费者厅和日本政府观光局页面制作 6 条可追溯安全知识摘要，建立中英文 BM25 检索、Pydantic 输出契约、最低相关性拒答和答案内引用；12 条正例得到 Hit@1 100%、Recall@3 95.8%，6 条库外查询全部拒答，作为混合检索的消融基线。
- 在写稠密检索前冻结 12 条语义改写和 8 条难负例，再用开发集选定 0.60 余弦阈值；实现可选 FastEmbed adapter、L2 归一化、RRF 融合、分项分数审计和项目内模型缓存。盲测中 hybrid 的 Hit@1 从 BM25 的 58.3% 提升到 66.7%，但 Hit@3 与拒答均未改善且最终报告 P50 增加约 19.6 ms，因此保留 BM25 为默认，而不是把“用了向量”包装成升级。
- 增加显式 `session_id` 的短期结构化记忆，只保存位置、可信坐标和偏好，并用 TTL、LRU 上限、会话隔离、显式覆盖与清除接口控制状态；未提供 session 的请求保持无状态。
- 把 booking 授权从模型判断移到确定性服务层：首次请求只创建绑定会话的 pending action，独立 approve/reject 端点原子消费一次性令牌。默认 dry-run 不发送外部请求，测试证明批准前零调用、拒绝零调用、跨会话/重放零调用。
- 在不复制 Agent 流程的前提下给 LangGraph 节点加入 observer，将规划、工具、验证、恢复、记忆和等待确认转成版本化 SSE 事件；工具失败时前端能看到一次有界恢复，最终事件仍返回完整可审计 trace。

## 结果如何表达

当前结果证明“DeepSeek 语义规划 + 确定性策略”在开发集和首次冻结留出集上都优于关键词规则，但不能外推到生产环境。真实天气和 POI 链路可由内部 Agent 直连、内部 MCP Client 或外部 MCP Host 复用，并验证了位置消歧、偏好证据和故障处理。知识工具已从 Mock 升级为带官方链接的可切换检索层；盲测证明当前通用向量模型只带来有限首位排序收益，所以默认仍是 BM25。翻译仍是 Mock。后续需要扩大知识库、建立新的未消费测试集再比较领域向量模型与 Rerank，并增加多次 Planner 重复实验和工具参数准确率。

## 面试中的真实性边界

这是基于实习业务场景完成的个人重构，不复用公司源代码与私有数据。应分别说明“实习中参与验证的部分”和“个人作品集中重新设计并实现的部分”，不能把个人新增模块描述成原公司已经上线的功能。
