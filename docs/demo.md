# 3 分钟离线演示

## 演示前准备

安装开发依赖后，从项目根目录运行：

```bash
python scripts/demo_portfolio.py
```

脚本固定使用 Rule Planner、Mock tools 和 Dry-run booking gateway，不读取 API Key、不访问网络，也不会产生真实预订。脚本内置断言，任一安全或生命周期契约回退都会以非零状态退出。

## 推荐讲解顺序

### 0:00–0:30：项目定位

“这不是聊天壳。用户请求会经过结构化规划、确定性策略、工具执行、结果验证和一次有界恢复；每一步都进入 trace，也能通过 SSE 暴露给客户端。”

### 0:30–1:10：复合工具计划

第一段输入同时包含位置、素食偏好和日语表达需求。展示输出中的 `intents` 与 `tools`，说明 POI 和翻译工具来自同一份结构化计划，参数受 Pydantic Schema 与工具白名单约束。

### 1:10–1:40：有界会话记忆

第二段先保存大阪站和素食偏好，再发出“附近找一家餐厅”。展示 `memory_recalled` 只有 `location` 与 `preferences`，强调系统不把无限聊天历史和工具输出反复塞回模型。

### 1:40–2:20：有副作用操作的确认边界

第三段展示预订请求在确认前 `executions=0`，随后用独立确认对象批准。默认 gateway 返回 `external_request_sent=false`；同一令牌再次提交得到 `invalid_or_expired`。强调授权和幂等由确定性服务层实现，不交给 LLM 猜测。

### 2:20–2:50：可观察的 Agent 生命周期

最后展示 SSE 事件序列，包括规划、两个工具、验证和最终响应。说明事件来自真实节点和工具调用前后，不是前端模拟进度。

### 2:50–3:00：结果与边界

“系统验收首次是 90%，保留失败报告；修复通用意图消歧后，同哈希回归达到 100%。这个分数是确定性契约门禁，不代表真实模型或外部数据的生产准确率。”

- 生产化缺口：重点说明内存会话、鉴权、真实 booking gateway、供应商幂等对账与 SSE 背压。
